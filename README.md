# Codeva — лабораторна робота № 2

Семантична розмітка чотирьох сторінок: головна, каталог, деталі курсу та запис
на курс. Джерело структури й контенту — сторінка **03 Desktop 1440** у `WEB.fig`.
Стилізація належить до ЛР3, інтерактивні фільтри та оброблення форми — до ЛР4.

## Запуск і перевірка

```sh
npm ci
npm run dev
```

Відкрийте адресу, яку надрукує Vite. Якщо PowerShell блокує `npm.ps1`,
використовуйте `npm.cmd` замість `npm`.

```sh
npm run lint
npm run preview
```

Команда `lint` збирає всі чотири сторінки та перевіряє готовий HTML і конфігурації
через ESLint. Для W3C Nu Html Checker використовуйте HTML-файли з `dist/`.

Публікуйте **вміст `dist/`**. Сторінки `src/*.html` також містять готову розмітку:
їх можна відкривати безпосередньо або через Live Server. Відносні адреси працюють
і під підкаталогом репозиторію. Кореневий `index.html` перенаправляє на готову головну
сторінку в `src/`; збірка використовує окрему головну сторінку.

## Повторювані блоки та schema.org

- `src/partials/header.ejs` — спільна шапка з активним пунктом навігації.
- `src/partials/footer.ejs` — спільний підвал.
- `src/partials/course-card.ejs` — картка курсу для головної та каталогу.
- `src/index.html`, `src/list.html`, `src/details.html`, `src/form.html` — чотири
  основні сторінки; їхній власний вміст редагується безпосередньо в HTML.
- `src/data/courses.json` — шість курсів із desktop-макета.
- `src/details.html` — структуровані дані schema.org типу `Course` у JSON-LD.

EJS виконується в Node.js лише для трьох повторюваних блоків: шапки, підвалу
та картки. Окремих EJS-шаблонів цілих сторінок немає. Генератор оновлює в HTML
ділянки між коментарями `Початок EJS:…` і `Кінець EJS:…`, зберігаючи решту вмісту.
Параметр `active` визначає активну сторінку в навігації, а `course` містить
ідентифікатор курсу з `src/data/courses.json`.

Власний вміст сторінки редагуйте у відповідному HTML поза позначеними ділянками.
Шапку, підвал і вигляд карток змінюйте у `src/partials/`, дані карток — у
`src/data/courses.json`. Не видаляйте коментарі-межі спільних блоків.

Браузер завжди отримує готовий HTML, тому працюють Vite, Live Server і відкриття
файлів напряму. Vite автоматично оновлює спільні блоки під час редагування.
Для Live Server або відкриття файлів без Vite після зміни спільних шаблонів виконайте:

```sh
npm run render
```

## Адаптивні зображення

Картки використовують згенеровану демонстраційну фотографію робочого місця
з ноутбуком. Оригінал — `src/assets/img/course-photo-original.png`.
Для інструкторки використано згенерований демонстраційний жіночий портрет.
Оригінал — `src/assets/img/instructor-photo-original.png`.
Кожне зображення має три розміри в обох форматах — JPG і WebP:

| Зображення | Малий розмір | Середній розмір | Великий розмір |
| --- | --- | --- | --- |
| Прев’ю курсу | 340 × 180 | 680 × 360 | 1360 × 720 |
| Аватар викладача | 80 × 80 | 160 × 160 | 320 × 320 |

`picture` надає WebP із резервним JPG, `srcset` перелічує три розміри,
а `sizes` описує ширину відображення. Браузер обирає файл за шириною місця для
зображення та щільністю пікселів: це не жорстка прив’язка файла до пристрою.
Для поточної розмітки `sizes` описує ширину до 680 px: на вузькому екрані
враховано 56 px стандартних відступів сторінки та списку, а від 736 px
використовується 680 px. Після оформлення сітки в ЛР3 `sizes` потрібно узгодити
з новою шириною карток.
Аватар зберігає ширину відображення 80 px на всіх екранах.
Для пропорційного зменшення фотографій у вузькому вікні підключено мінімальний
файл `src/styles/images.css`: `max-width: 100%` та `height: auto`.
Фото не виходять за ширину контейнера й не обрізаються; на широкому екрані
зберігають задану в HTML ширину. Повне оформлення макета залишається для ЛР3.

## Підготовка до перекладів

Словник англомовного інтерфейсу: `src/i18n/en.json`.

- `data-i18n` містить ключ перекладу текстового вузла.
- `data-i18n-placeholder` позначає переклад підказки поля.
- `data-i18n-aria-label` позначає переклад доступної назви елемента.
- Ключі `catalog.<id>.<field>` пов’язують картки зі словником за ідентифікатором курсу.

Це підготовка структури: перемикач мови та завантаження перекладів поки не потрібні.
Заголовок головної має окремі ключі для звичайного й акцентного тексту, щоб
майбутня заміна тексту не знищила вкладений `span`.

## Форма

Видимі поля відповідають desktop-макету; вибраний курс передається прихованим
полем. Перевірка імені та електронної адреси працює засобами браузера.
`/enroll` — майбутня адреса обробника для ЛР4, а не реалізований сервіс
статичного хостингу.

## Фінальна перевірка ЛР2

- Збірка Vite та ESLint проходять без помилок.
- Чотири готові сторінки проходять W3C Nu Html Checker без помилок і попереджень.
- У Chrome перевірено ширини 360, 390, 768, 1280 і 1440 px: фотографії зберігають
  пропорції, не обрізаються й не створюють горизонтального прокручування.
- На кожній сторінці перевірено видимий Tab-фокус і перехід клавішею Enter
  з `Skip to content` до основного вмісту.
- Перевірено відносні адреси, зображення, підписи полів, ключі i18n та структуру JSON-LD.

Перед здачею збережіть зміни в потрібному репозиторії GitHub Classroom та оновіть
preview готовими файлами. Перевірка локальної збірки не оновлює опублікований сайт.
